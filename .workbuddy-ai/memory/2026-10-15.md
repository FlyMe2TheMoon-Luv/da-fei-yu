# 2026-10-15 · 真机验收卡在「读不到 hosts」

## 现象

主人在真机验收第 2 步（加 `bilibili.com` → 开始专注）时，界面报：
「读不到 hosts 文件，没法开始专注。可能是被杀毒软件挡住了，或者权限不够。」

## 排查结论（全是实测，不是猜）

- hosts 文件本身没问题：`C:\Windows\System32\drivers\etc\hosts` 存在、824 字节；
  当前身份 `kilin\flyme`（**非管理员**）读得好好的；ACL 里 `BUILTIN\Users` 有 ReadAndExecute。
- PowerShell 能读、`node.exe` 能读、**Electron 也能读** —— 用程序自己的
  `intercept.readHostsText()` 在 Electron 里跑，返回 824 字符，不是 null。
- 启动器（`launcher/*.bat|vbs`）干净，没设任何环境变量；HKCU / HKLM 里也没有残留的 `PET_*`。
- 机器上装了 **火绒安全软件**（`HipsDaemon` / `HipsTray` / `wsctrlsvc` 在跑）。
- 结论：**代码路径没问题，是运行那一刻被外部挡住了**（最可能是火绒 HIPS 拦了一下）。
  沙箱里复现不出来 —— 这类问题只能靠「把错误码带出来」定位。

## 本轮改了什么

1. **不再吞错误**（根因：`readHostsText` 的 `catch { return null }` 把原因丢了，
   界面只能说一句「可能是杀软，也可能权限不够」—— 那是**猜**，主人没法照做）：
   - `intercept.js`：新增 `lastReadError`（记 code / message / path）、`readError()`、
     `explainReadError()`（把 ENOENT / EACCES|EPERM / EBUSY / 其它 翻成**四句不同**的人话）。
     ★ 读成功必须把旧原因清掉，否则会拿上次的错去解释这次。
   - `focus/index.js`：读失败时带上「意思 + 错误码」，并往控制台打一行
     `[focus] 读 hosts 失败：path=… code=… msg=…`。
2. **新增一键体检** `npm run check:hosts`（`scripts/check-hosts.js`，**只读、不写、不提权**）。
   真实 hosts → ✅ 824 字符；故意给坏路径 → ❌ ENOENT + 人话 + 「怎么办」。

# 真凶找到了：错误码 `ERR_INVALID_ARG_TYPE`（不是杀软，是我们自己的接线 bug）

## 主人反馈（两张图）

1. `npm run check:hosts` → ✅ 读到了 824 字符（**退出火绒后仍然如此**）。
2. 点「开始专注」的报错：**「…系统没给出具体原因（错误码 ERR_INVALID_ARG_TYPE）」**。

`ERR_INVALID_ARG_TYPE` **不是「读不到文件」**，是「传进来的参数类型不对」。
两边一对照就锁定了：文件读得好好的，是我们**拿着一个错的路径去读了**。

## 根因

`src/main/focus/index.js` 原来是：

```js
const elevator = require('./elevate').createElevator();   // ← 这是**实例**
let options = { elevate: true, hostsPath: elevator.HOSTS_PATH };  // ← 实例上没有这个字段！
```

实测（`node tmp/probe-hosts-path.js`）：

```
模块上的 HOSTS_PATH : "C:\Windows\System32\drivers\etc\hosts"
实例上的 HOSTS_PATH : undefined          ← 真凶
```

`HOSTS_PATH` 只在**模块导出**里（`elevate.js:285`），`createElevator()` 的返回对象
（`elevate.js:268-281`）**没有它**。于是 `fs.readFileSync(undefined)` →
`ERR_INVALID_ARG_TYPE`。

★ **自检为什么全绿**：沙箱时 `main.js` 会 `init({hostsPath: <假文件>})` 把它**覆盖掉**，
所以所有自检看到的都是被覆盖后的正确路径 —— 那个 `undefined` 从来没被看过一眼。
（又一次印证项目那条老坑：`require('./elevate')` 当实例用，纯函数自检抓不到。
这次是**反过来**：从实例取常量。）

## 修

- `focus/index.js`：常量从**模块**取、实例从**工厂**取：
  ```js
  const elevatorMod = require('./elevate');
  const elevator = elevatorMod.createElevator();
  ...
  hostsPath: elevatorMod.HOSTS_PATH,
  ```

## 新增：`npm run test:focus-wiring`（17 通过 / 0 失败，负对照 7/7）

**专抓「自检全绿、真机必挂」的接线/默认值错误。** 这是本轮最有价值的产出。

它干四件事：
1. 验证 `elevate` 模块有 `HOSTS_PATH`、实例**没有**（负对照：实例上确实没有）。
2. **静态读源码**（先剥注释，否则注释里提到的错误写法会误判）：
   禁止 `elevator.HOSTS_PATH`、要求 `elevatorMod.HOSTS_PATH`，并检查声明顺序。
3. **真的用 electron 二进制**加载 `index.js`（**不调 init**），读出模块级默认 `hostsPath` ——
   这正是主人真机上用的那个值。`require('electron')` 在普通 Node 下返回二进制路径。
4. 检查 `main.js` 只在沙箱时覆盖 `hostsPath`。

★ 破坏测试：把 `elevatorMod.HOSTS_PATH` 改回 `elevator.HOSTS_PATH` → 自检 **4 条红**，
且第 4 节直接印出 `实际 undefined`。抓得死死的。

★ 踩到的两个自检自身的坑：
- `spawnSync` 探针走管道会 `EBUSY` → 改成「探针写文件、父进程读文件」。
- e2e 里我加的第一版断言写「默认 hostsPath 形如 …\\hosts」是**不可能通过的**
  （e2e 跑到那步时 init 已经把它换成沙箱路径了）→ 改成只断「不是 undefined」，
  并在注释里写明「真正盯真机默认值的是 test:focus-wiring」。**验证方式本身也可能是假的**，又一次。

### 自己抓出的两条「装饰性断言」（最重要）

**① 量「过渡中的属性」= 假断言。**
验「按下按钮会缩小」，我在发完 `pointerdown` 后**立刻**读 `getComputedStyle().transform`，
读到 `matrix(1,0,0,1,0,0)`（scale 1，**根本没变**）—— 因为 transform 有 110ms 过渡。
而我的断言写的是 `transform !== 'none'`，于是**「什么都没变」照样绿**。
→ 修法：等过渡落地（260ms）再量，并**量绝对数值**（`scale < 1`）。
现在的输出很能说明问题：`立刻 matrix(1,…) → 稳定后 matrix(0.97,…)（scale=0.97）`。
★ 一般规律：**断言「不为空 / 不为 none」≈ 没断言**，要量出具体数字。

**② 三张截图字节数一模一样 = 模式没切过去。**

## v4 批次 2.6 完成：退出专注改「按住进度条」+ 专注页打磨（等主人确认）

**主人的原话：** 「把退出专注模式做成进度条 按照苹果的设计原则」

**先问清的三件事（主人都选了推荐项）：** ① 交互＝**按住不动，条自己涨满**；
② 分工＝**各管各的：圆环是剩余时间，进度条只管退出**；③ 范围＝**顺便把专注页整体打磨一下**。

### 做了什么

1. **退出按钮变成进度条**：三层结构 —— 轨道（`::before`）/ 填充（`.focus-stop-fill`，
   `transform: scaleX(var(--hold))`）/ 盖在上面的文字。`--hold` 0→1 由 JS 每帧（rAF）写。
2. **松手立刻回退**（160ms `--ease-out`），按住期间**不加过渡**（跟手）。
   涨上去是**线性、时长＝主进程给的 `holdMs`**，不额外加 easing。
3. **难度一点没变**：仍然要按满 3 秒，而且**是不是够 3 秒仍然由主进程裁定**
   （`api.focusStop({pressedAt})`）—— 界面只画进度，不判规则。
4. **键盘也能退**：空格/回车按住；因为键盘会连发 keydown，用 `holdKeyDown` 标志
   保证只从第一次开始计时。
5. **秒数只有一个来源**：`holdSeconds()`（读 `focusData.holdMs`）。
   按钮文字、还没开始时的说明、松手太早的提示 —— 三处都从它来，不再各写一个「3 秒」。
6. **专注页 token 化打磨**：`.focus-add input` 不再写死 `background:#fff` / `border-radius:7px`
   （深色主题下是一块白板、且和 `.field input` 的 `--r-sm` 不一致）；
   `#focus-custom-row input` 补上 focus 态；`.focus-col-head` 改成「小标签」样式
   （`--fs-micro` + 正字距；**去掉 `text-transform: uppercase`** —— 中文标签用不上，纯摆设）；
   两个空名单加了占位说明（`:has(> .focus-list:empty)`，不需要 JS 管）；
   `#focus-doh` 三态统一（`unknown` 加左侧竖线做标记；`ok` 不再写死深绿 `#0d7a48`，深色下看不见）；
   补 hover/focus-visible/降低动效/提高对比度的覆盖；`.focus-hint:empty` 不占位（避免卡片跳动）。
7. **`window.__focusHoldDebug`**（**只读**）：自检可以问「进度多少 / 在不在按住 / 按了多久 / 需要多久」，
   不用靠等固定毫秒数去猜。刻意**只暴露读**，免得自检能伪造进度。

1. **`spawnSync` 在本机沙箱里会 `EBUSY`**（连 `spawnSync('node',['-v'])` 都失败），
   而**异步 `spawn` 正常**。→ 全脚本统一改用异步 `spawn`。
   ★ 顺带发现：项目里 `test-focus-wiring` 早就踩过同一个坑（探针走管道 EBUSY → 改成写文件再读）。
2. **`git()` 用 `spawnSync` + `catch` 兜底成 `[]` = 最危险的一种「假绿」**：
   git 起不来时会**静默地一套都不跑**，界面还显示「没有改动」。
   → 改成：起不来**必须抛错**，并提示「挑不出来就直接 `npm run test:all`」；
   `--selfcheck` 里专门加了一条负对照钉死它（用假二进制名触发 ENOENT）。
   ★ 这就是项目那条老教训的又一例：**凡是 catch 完只返回兜底值的地方，都在丢诊断信息**。
