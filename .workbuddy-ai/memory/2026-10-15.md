# 2026-10-15 · 真机验收卡在「读不到 hosts」

## 现象

主人在真机验收第 2 步（加 `bilibili.com` → 开始专注）时，界面报：
「读不到 hosts 文件，没法开始专注。可能是被杀毒软件挡住了，或者权限不够。」

## 排查结论（全是实测，不是猜）

- hosts 文件本身没问题：`C:\Windows\System32\drivers\etc\hosts` 存在、824 字节；
  当前身份 `kilin\flyme`（**非管理员**）读得好好的；ACL 里 `BUILTIN\Users` 有 ReadAndExecute。
- PowerShell 能读、`node.exe` 能读、**Electron 也能读** —— 用程序自己的
  `intercept.readHostsText()` 在 Electron 里跑，返回 824 字符，不是 null。
- 启动器（`launcher/*.bat|vbs`）干净，没设任何环境变量；HKCU / HKLM 里也没有残留的 `PET_*`。
- 机器上装了 **火绒安全软件**（`HipsDaemon` / `HipsTray` / `wsctrlsvc` 在跑）。
- 结论：**代码路径没问题，是运行那一刻被外部挡住了**（最可能是火绒 HIPS 拦了一下）。
  沙箱里复现不出来 —— 这类问题只能靠「把错误码带出来」定位。

## 本轮改了什么

1. **不再吞错误**（根因：`readHostsText` 的 `catch { return null }` 把原因丢了，
   界面只能说一句「可能是杀软，也可能权限不够」—— 那是**猜**，主人没法照做）：
   - `intercept.js`：新增 `lastReadError`（记 code / message / path）、`readError()`、
     `explainReadError()`（把 ENOENT / EACCES|EPERM / EBUSY / 其它 翻成**四句不同**的人话）。
     ★ 读成功必须把旧原因清掉，否则会拿上次的错去解释这次。
   - `focus/index.js`：读失败时带上「意思 + 错误码」，并往控制台打一行
     `[focus] 读 hosts 失败：path=… code=… msg=…`。
2. **新增一键体检** `npm run check:hosts`（`scripts/check-hosts.js`，**只读、不写、不提权**）。
   真实 hosts → ✅ 824 字符；故意给坏路径 → ❌ ENOENT + 人话 + 「怎么办」。

## 自检

- `test-focus-intercept`：47 → **56 通过 / 0 失败，负对照 36/36**（新增 section 2b）。
- 破坏测试（都如期变红）：去掉「读成功清旧原因」→ 1 红；`explainReadError` 恒返同一句 → 2 红。
